# Local development

This is for working on Veto itself. To use Veto, start with the
[quickstart](quickstart.md).

## What you need

- Go 1.24 or newer, for the server.
- Node.js 24 (see `.nvmrc`) and pnpm 10, for the console and the TypeScript SDK.
  The console runs on Node 22.12 too; [portless](https://github.com/vercel-labs/portless),
  which gives the dev servers their names, needs Node 24.
- PostgreSQL 14 or newer. `make db` starts one in Docker.
- Python 3.10 or newer, only for the Python SDK.

## Named URLs instead of port numbers

Veto's dev servers run behind portless, so you open
`https://veto.localhost` for the console and `https://api.veto.localhost`
for the API instead of remembering ports. portless picks free ports, starts
a local HTTPS proxy, and trusts its own certificate authority on first run
(it may ask for your password to do that).

The names come from `portless.json` at the repository root:

| Package        | Address                      |
| -------------- | ---------------------------- |
| `apps/console` | `https://veto.localhost`     |
| `server`       | `https://api.veto.localhost` |

Using `.localhost` names also means the console and API are on the same
site, so cookies behave as they do in production.

## First run

```sh
make setup                      # pnpm install and go mod download
make db                         # PostgreSQL on localhost:5432, user and password "veto"
cp server/.env.example server/.env
go run ./server/cmd/vetod keygen   # paste the output into VETO_MASTER_KEY in server/.env
make dev
```

`make dev` runs `pnpm dev`, which starts both apps through portless and
turbo. vetod migrates the database when it starts. Open
`https://veto.localhost` and create a workspace.

To run one side only: `make dev-server` or `make dev-console`. Without
portless, run `PORTLESS=0 pnpm --filter @veto/console dev:app` and set
`VETO_API_URL` to wherever vetod listens, such as `http://127.0.0.1:8080`.

### How the console reaches the API

The browser only ever talks to the console. `apps/console/proxy.ts`
forwards `/v1/*` and `/mcp/*` to `VETO_API_URL`, which defaults to
`https://api.veto.localhost` in development. portless sets
`NODE_EXTRA_CA_CERTS` for the processes it starts, so Node trusts the local
certificate.

### A decision model in development

Set `VETO_JEV_API_KEY` in `server/.env` to call TypeSafe System One. Without
it, policies still decide what they can and everything else waits for a
person, which is enough to work on most of the console. The playground page
shows the exact request Veto would send even with the model turned off.

## Tests

```sh
make test
```

- Go: `cd server && go test ./...`. Tests that need PostgreSQL read
  `VETO_TEST_DATABASE_URL`, create a fresh database per test, and drop it
  afterwards; without the variable they are skipped. With `make db`
  running:

  ```sh
  export VETO_TEST_DATABASE_URL=postgres://veto:veto@localhost:5432/postgres?sslmode=disable
  ```

- Console: `pnpm --filter @veto/console test` runs unit tests;
  `lint` and `typecheck` run ESLint and TypeScript.
- TypeScript SDK: `pnpm --filter @shvgroups/veto test`.
- Python SDK: `cd sdks/python && pip install -e ".[test]" && pytest`.

`make check` runs everything CI runs except the image builds.

## Layout

```
server/            vetod: Go, one binary for the API, MCP proxy and workers
  cmd/vetod/       entry point and operator commands
  internal/        packages, described in docs/architecture.md
apps/console/      the console: Next.js, React, Tailwind
sdks/typescript/   @shvgroups/veto
sdks/python/       shvgroups-veto
api/openapi.yaml   the HTTP API, checked against the route table by a test
evals/             labelled cases for vetod eval
brand/             logo, banners and diagrams, generated by brand/build.py
deploy/            Docker Compose and the Helm chart
docs/              this documentation
```

## Conventions

- Go: `gofmt`, `go vet`, no global state, errors wrapped with context.
  Business rules live in `internal/app` and below; `internal/httpapi` only
  translates HTTP.
- TypeScript: strict mode with `noUncheckedIndexedAccess`. Server state
  goes through TanStack Query; the live event stream only invalidates
  queries, it never becomes a second source of truth.
- Copy in the console is sentence case, in plain words, and says what a
  control does. Errors say what went wrong and what to do.
- When you change the API, update `api/openapi.yaml`; the server's tests
  fail if a route is missing from it.
